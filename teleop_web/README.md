# 网页人工控制

在现有 RoboTwin 仿真环境中运行，不需要模型服务。使用现有机器人、任务资产和
`scripts/requirements.txt` 的依赖；网页使用原生 HTML/JavaScript，无需 Node 或前端构建。

```bash
cd /path/to/RoboTwin
python scripts/teleop_web.py \
  --task-name handover_block \
  --task-config demo_clean \
  --seed 0 \
  --port 8080
```

浏览器打开 `http://127.0.0.1:8080`。远端机器可以通过 SSH 转发访问：

```bash
ssh -L 8080:127.0.0.1:8080 user@simulation-host
```

也可按需要使用 `--host 0.0.0.0` 绑定机器网络接口。服务默认只绑定本机，未实现用户登录。

启动时可覆盖任务配置中的本体和相机：

```bash
python scripts/teleop_web.py \
  --task-name handover_block --task-config demo_clean \
  --embodiment aloha-agilex \
  --head-camera-type Large_L515 --wrist-camera-type Large_L515

# 左右独立安装的本体，第三个值为间距（启动参数使用米）
python scripts/teleop_web.py \
  --task-name handover_block --embodiment franka-panda franka-panda 0.6
```

本体选项直接来自 `env_cfg/task_config/_embodiment_config.yml`，相机选项来自
`env_cfg/task_config/_camera_config.yml`。未指定时沿用所选任务配置。
`L515` 为 320×180、垂直视场角 45°；`Large_L515` 为 640×360、45°。
默认 `D435` 为 320×240、37°；`Large_*` 只增加分辨率，不额外扩大视场角。
这些是仿真透视相机预设，不需要接入真实相机。

## 使用

- 启动参数确定初始 `task_name`、`task_config`、`seed`。页面也可选择任务和配置，
  修改 seed，再点击“重建所选场景”。同一 seed 重建当前配置；不自动寻找其他可用 seed。
- 页面可选择本体布局、注册本体，以及主/腕部相机预设，点击“重建所选场景”生效。
  “完整双臂本体”加载一套双臂机器人；“左右独立本体”分别加载左右机器人并设置间距
  （页面使用 cm）。选项不按本地资产过滤；资产缺失或不兼容时显示初始化错误。
- 初始化只调用任务的 `setup_demo()`，不执行专家 `play_once()`。场景初始化失败时，
  页面显示具体错误，仍可选择其他配置或重试。
- 页面显示主相机、左腕相机和右腕相机。缺少机器人资产、SAPIEN/CuRobo 或可用的
  渲染设备时，不能获得真实仿真画面；页面不会用示例图片替代。
- 左右控制面板分别接受 `Δx/Δy/Δz`（cm）和 `Δroll/Δpitch/Δyaw`（度）。
  “执行左臂”“执行右臂”只控制选中的机械臂；“双臂一起执行”执行两组输入。
  页面将 cm 除以 100 后发送，协议字段 `translation_m` 和仿真仍使用米。
  实际/目标位置、坐标轴长度的页面显示也使用 cm。
- 命令成功、失败或停止后，仅清零参与执行机械臂的平移与旋转输入，夹爪设置保留。
  校验失败或服务端拒绝时保留输入；运动期间禁用运动输入，避免覆盖下一条命令。
- 如需抓取，勾选“同时设置夹爪开合”，填写 `[0,1]` 开合目标，0 为闭合，1 为张开。
  不勾选时保留原开合目标。
- 一次只执行一条运动命令，忙碌时拒绝后续运动。一次双臂命令只有两侧规划均成功
  才开始执行。执行失败不会自动恢复先前物理场景。
- “停止当前运动”丢弃剩余轨迹，以当前实际关节位置建立保持目标。规划期间停止
  会等待当前规划调用返回并丢弃结果；期间不能发送新运动。重建场景可结束整个旧进程。
- 一个网页持有控制权，其他网页可以观看图像。控制页面断开时停止其正在执行的运动，
  释放控制权；重新连接或其他页面可获取控制权。
- “当前 episode 命令”按命令记录左右臂增量、夹爪目标、起始/目标/结束实际位姿、
  执行结果与到达误差（后端提供时）。点开记录查看详情；同一场景刷新或重连可恢复。
  历史只保存在服务端内存，重建场景后清空，服务退出后丢失，不写入磁盘。
  “状态日志”独立显示状态变化，清空日志不影响命令历史。

## 相对运动的定义

基准是服务端接受指令时读取的**实际 EE endpose**，不是上一条命令的目标、TCP 或
腕部相机坐标系。原始位姿格式为世界坐标 `[x,y,z,qw,qx,qy,qz]`。

```text
delta_R = Rz(yaw) @ Ry(pitch) @ Rx(roll)
p_target = p_actual + R_actual @ [dx, dy, dz]
R_target = R_actual @ delta_R
```

三个旋转角按右手规则取正；组合顺序为先 roll，再 pitch，再 yaw，三个轴固定为该次
命令开始时的 EE 局部轴。平移也沿起始 EE 局部轴，与本次旋转的中间结果无关。

纯旋转保持 EE 原点，TCP 会随姿态变化绕动：现有 RoboTwin 定义中
`p_TCP = p_EE + R_EE @ [0.12, 0, 0]`。不重复应用机器人配置中的轴向修正矩阵。

## 坐标轴显示

- 左腕画面显示左 EE 坐标系，右腕画面显示右 EE 坐标系；主画面同时显示两者。
- 左右开关分别控制该 EE 在所有相关画面中的显示，轴长可以调整，默认 `0.05 m`。
- X 红色、Y 绿色、Z 蓝色，正方向有箭头，主画面用 L/R 标注左右。
- 从与图像同一物理步的 EE 位姿和相机 OpenCV 内外参计算投影。轴线在前端 Canvas
  叠加，不创建物理对象，不执行深度遮挡；轴线可能显示在前景物体上方。
- 投影线段按近/远裁剪面及画面边界裁剪。EE 原点在画面外时，角落另显示“EE 轴向”
  指示器；这是方向提示，不表示 EE 原点在角落。⊙ 表示朝向相机，⊗ 表示背向相机。

## 执行与传输

仿真放在独立的 spawn 进程中，场景重建会关闭旧进程及其规划子进程。
所有 SAPIEN 场景读取、驱动、物理推进、渲染和取图都在该进程的主线程。
规划线程只使用主线程提前复制的关节状态和目标，不读取场景。

规划使用当前 CuRobo 后端及已有的 EE 到末端 link 转换；保留其已有碰撞配置。
这不额外提供完整场景障碍物或双臂之间的联合避碰保证。
规划时冻结物理推进，继续刷新图像；执行及空闲时推进物理。
轨迹按 CuRobo 的 `1/250 s` 插值时间执行，较短一侧完成后保持目标。

执行后等待实际末端到达，超过 2 秒仿真时间仍未达到容差则报告失败。
默认位置容差 `0.005 m`、旋转容差 `3°`。夹爪显示实际开合值、目标和误差，
抓住物体时实际开合值可能无法达到闭合目标，这不作为末端运动失败的判据。
页面显示实际位姿、目标位姿、到达误差，以及 task 自身 `check_success()` 的结果。
不会把轨迹执行完毕当作任务成功。

HTTP 与两个 WebSocket 共用一个端口：

| 端点 | 用途 |
| --- | --- |
| `/` | 网页 |
| `/api/state` | 当前场景、控制状态与当前 episode 命令历史 |
| `/api/catalog` | task、task config、本体与相机预设列表 |
| `/ws/control` | JSON 命令、控制权和执行结果 |
| `/ws/frames` | 三路同步 JPEG 帧包 |

帧包为：4 字节大端 JSON 头长度、UTF-8 JSON、按头部 `cameras` 顺序排列的 JPEG。
头部包含每张 JPEG 的字节数、相机内参、EE 相机坐标系原点/轴向、scene/frame ID、
采集时间和仿真时间。三路图像完成解码后同时更新。发送和解码均只保留最新待处理帧。

可调启动参数：

```bash
python scripts/teleop_web.py --help
# --fps 10 --jpeg-quality 80
# --position-tolerance 0.005 --rotation-tolerance 3
```

`--fps` 是采集频率上限，实际帧率和仿真速度取决于渲染及计算耗时。页面显示实际帧率，
超过 3 秒没有更新会标记画面过期。

## 验证

在有 NumPy、PyYAML、websockets 的环境中可独立检查几何、命令协议和控制流程：

```bash
python -m pytest -q tests/test_teleop_web.py
node tests/teleop_overlay_test.mjs
node tests/teleop_controls_test.mjs
```

测试中的控制替身只验证状态和执行顺序，不模拟物理，不能替代 SAPIEN 验收。
完整环境还需验证真实任务初始化、左右/双臂局部运动、旋转中心、夹爪抓取、运动期间
持续出图、坐标轴投影、中途停止和场景反复重建。
